# Appendix F: Prompt Templates for Vibe Coding

Ten tested prompt templates for common vibe coding tasks. Copy them. Adapt the bracketed sections. Use them as starting points; refine as you learn what works for your specific AI assistant.

## 1. Start a New Project

```
I want to build [describe product in one sentence].

Tech stack: [React + TypeScript + Vite / Next.js / etc.]
Database: [Supabase / Firebase / none]
Auth: [Supabase Auth / Clerk / none]

The MVP needs exactly these features:
1. [Feature one]
2. [Feature two]
3. [Feature three]

NOT in scope: [list things you explicitly don't want yet]

Start with the project structure. Show me the folder layout and the initial files I need to create.
```

## 2. Debug an Error

```
I'm getting this error:

[Paste the full error message and stack trace]

This happens when I [describe what you were doing when the error occurred].

The relevant code is:

[Paste the relevant file or function]

What's causing this error and how do I fix it?
```

## 3. Add a Feature to Existing Code

```
I have an existing [describe app type] built with [tech stack].

Current behaviour: [what the app does now]

I want to add: [describe the new feature in detail]

Here's the current code for the relevant file:

[Paste the file]

Show me the changes needed. Preserve existing functionality. Use the same coding style.
```

## 4. Explain Code I Don't Understand

```
Explain this code to me as if I'm a non-programmer. For each section:
1. What does it do in plain English?
2. Why is it written this way?
3. What would break if I removed or changed it?

[Paste the code]
```

## 5. Write Tests

```
Write tests for this function:

[Paste the function]

I need:
- 2 tests for normal/expected behaviour
- 1 test for an edge case (empty input, zero, boundary value)
- 1 test for an error condition (what should happen when it fails)

Use [Jest / Vitest / Playwright] syntax. Each test should have a clear, descriptive name.
```

## 6. Security Review

```
Review this code for security vulnerabilities. Check specifically for:

1. Exposed secrets or API keys
2. SQL injection risks
3. XSS vulnerabilities
4. Broken access control (can User A access User B's data?)
5. Missing input validation
6. Insecure cookie configuration

[Paste the code or describe the architecture]

For each issue found: describe the vulnerability, show the vulnerable line, and provide the fix.
```

## 7. API Integration

```
I need to integrate with [API name] in my [tech stack] project.

I want to: [describe what you want to do with the API]

Show me:
1. How to install any needed packages
2. The function that calls the API (with error handling)
3. How to handle rate limits
4. Where to store the API key safely

Use environment variables for secrets. Never put keys in frontend code.
```

## 8. Database Schema Design

```
I'm building [describe the app]. I need a database schema.

The app needs to store:
- [Entity 1: describe fields and relationships]
- [Entity 2: describe fields and relationships]
- [Entity 3: describe fields and relationships]

Users should only see their own data.
I'm using [Supabase / Firebase / PostgreSQL].

Show me:
1. The table/collection structure
2. Row-Level Security policies (if Supabase) or Security Rules (if Firebase)
3. Example queries for the most common operations (create, read, update, delete)
```

## 9. Deploy Configuration

```
I have a [describe project type] built with [tech stack].

I want to deploy to [Vercel / Render / Netlify].

The project needs these environment variables:
- [List each variable and whether it's public or secret]

Show me:
1. Any build configuration needed
2. How to set environment variables on the platform
3. How to set up auto-deploy from GitHub
4. A health check endpoint for monitoring
```

## 10. Refactor AI-Generated Code

```
This code was generated by an AI assistant and works, but I want to improve it.

[Paste the code]

Please:
1. Add TypeScript types to all functions and variables
2. Extract repeated logic into reusable functions
3. Add error handling where it's missing
4. Add comments only where the code's purpose isn't obvious from the names
5. Flag any security concerns

Keep the same functionality. Show me the refactored version with a brief explanation of each change.
```

## Using These Templates Effectively

**Be specific.** "Build me a website" produces generic output. "Build me a landing page for a Portuguese coffee shop with a menu section, an about section, and a contact form that saves to Supabase" produces useful code.

**Include context.** Paste your existing code, your error messages, your tech stack. The more context the AI has, the more relevant its response.

**Iterate.** The first response is a starting point. Ask follow-up questions: "Now add error handling to the fetch call." "Make the form responsive on mobile." "Add loading states."

**Verify.** AI-generated code can be wrong. Test it. Read it. If something looks odd, ask: "Explain why you used [specific approach]. Is there a security concern?"

## 11. Add Support for a New Platform (ATS, Marketplace, etc.)

This is the template you'd use to extend JobPilot to a new job site, or to extend any project to a new integration:

```
I have a Chrome extension that auto-fills job application forms on Greenhouse.

It works by:
1. Content script extracts form field names from the page
2. Service worker sends field names + user profile to OpenAI
3. OpenAI returns a JSON mapping of field names to profile values
4. Content script fills each field

I want to add support for [new platform, e.g., Lever / Workday / LinkedIn Easy Apply].

Here's my current content script for Greenhouse:

[Paste content script]

Please:
1. Analyse [new platform]'s form structure (typical field names, DOM layout, any iframes or shadow DOM)
2. Write a new content script (or modify the existing one) to extract fields from [new platform]
3. Note any differences in how the form needs to be filled (dropdowns vs text inputs, file uploads, multi-step forms)
4. Flag any permission changes needed in manifest.json
```

This template works for any project that needs to support a new integration, not just job applications. Replace the ATS names with whatever platforms you're targeting.
